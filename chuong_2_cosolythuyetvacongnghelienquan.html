Chương 2. Cơ sở lý thuyết và Công nghệ liên quan

2.1. Kiến trúc Client-Server

2.1.1. Định nghĩa

Kiến trúc Client-Server là một mô hình phân tán trong đó các nhiệm vụ được phân chia giữa nhà cung cấp tài nguyên hoặc dịch vụ (Server) và người yêu cầu dịch vụ (Client). Client gửi yêu cầu (request) đến Server, Server xử lý và trả về kết quả (response).

2.1.2. Đặc trưng

  • Tách biệt rõ ràng: Giao diện người dùng và logic xử lý nghiệp vụ được phát triển độc lập, giúp dễ bảo trì và mở rộng.
  • Tập trung hóa dữ liệu: Toàn bộ dữ liệu được lưu trữ và quản lý tại Server, đảm bảo tính nhất quán.
  • Khả năng mở rộng: Có thể nâng cấp Server hoặc thêm Server mới mà không ảnh hưởng đến Client.

2.1.3. Ứng dụng trong SalonHub

SalonHub áp dụng kiến trúc Client-Server với Client là ứng dụng React.js chạy trên trình duyệt, Server là ứng dụng Node.js/Express.js xử lý logic và tương tác với cơ sở dữ liệu MySQL. Hai phần giao tiếp với nhau qua giao thức HTTP/HTTPS dưới dạng dữ liệu JSON.

2.2. Kiến trúc RESTful API

2.2.1. Định nghĩa

REST (Representational State Transfer) là một kiểu kiến trúc phần mềm cho hệ thống phân tán. RESTful API là giao diện lập trình ứng dụng tuân theo các nguyên tắc REST, sử dụng giao thức HTTP để thao tác trên tài nguyên (resources).

2.2.2. Đặc trưng

  • Phi trạng thái (Stateless): Mỗi request từ Client phải chứa đủ thông tin để Server xử lý, Server không lưu trạng thái phiên.
  • Phương thức HTTP chuẩn: GET (truy vấn), POST (tạo mới), PUT/PATCH (cập nhật), DELETE (xóa).
  • Tài nguyên được định danh qua URI: Mỗi tài nguyên có địa chỉ URL duy nhất, ví dụ: /api/appointments/123.
  • Định dạng JSON: Dữ liệu trao đổi nhẹ, dễ đọc và dễ phân tích.

2.2.3. Ứng dụng trong SalonHub

Toàn bộ giao tiếp giữa Frontend và Backend của SalonHub đều thông qua RESTful API. Ví dụ: GET /api/services để lấy danh sách dịch vụ, POST /api/appointments để tạo lịch hẹn mới, PATCH /api/orders/:id để cập nhật trạng thái đơn hàng.

2.3. Node.js

2.3.1. Định nghĩa

Node.js là một môi trường thực thi JavaScript (Runtime Environment) phía máy chủ, được xây dựng trên Engine V8 của Google Chrome. Node.js cho phép sử dụng JavaScript — ngôn ngữ vốn chỉ chạy trên trình duyệt — để phát triển ứng dụng phía Server.

2.3.2. Đặc trưng

  • Non-blocking I/O: Xử lý bất đồng bộ, không chờ đợi tác vụ I/O hoàn thành mới xử lý tiếp, giúp phục vụ hàng ngàn kết nối đồng thời.
  • Đơn luồng (Single-threaded): Sử dụng vòng lặp sự kiện (Event Loop) để xử lý nhiều request trên một luồng duy nhất.
  • NPM: Hệ thống quản lý thư viện lớn nhất thế giới với hơn 1,3 triệu gói (packages).

2.3.3. Ứng dụng trong SalonHub

Node.js là nền tảng chạy toàn bộ Server Backend của SalonHub, xử lý các API về đặt lịch, thanh toán, quản lý kho và kế toán. Cơ chế bất đồng bộ giúp hệ thống xử lý đồng thời nhiều yêu cầu từ khách hàng và các Webhook từ SePay mà không bị tắc nghẽn.

2.4. Framework Express.js

2.4.1. Định nghĩa

Express.js là một framework tối giản (minimalist) và linh hoạt dành cho Node.js, cung cấp bộ tính năng mạnh mẽ để xây dựng ứng dụng web và API. Express là framework phổ biến nhất trong hệ sinh thái Node.js.

2.4.2. Đặc trưng

  • Middleware: Các hàm có quyền can thiệp vào vòng đời request-response, phục vụ xác thực, ghi log, xử lý lỗi.
  • Routing linh hoạt: Hệ thống định tuyến mạnh mẽ, hỗ trợ phân nhóm route và tham số động.
  • Nhẹ và mở rộng: Chỉ cung cấp các tính năng cốt lõi, phần còn lại được bổ sung qua các middleware bên ngoài.

2.4.3. Ứng dụng trong SalonHub

Express.js được sử dụng để xây dựng toàn bộ hệ thống API của SalonHub. Các middleware tùy chỉnh được viết để xác thực JWT, kiểm tra phân quyền theo vai trò (admin, staff, accountant, customer), và xử lý lỗi tập trung.

2.5. React.js

2.5.1. Định nghĩa

React là một thư viện JavaScript mã nguồn mở được phát triển bởi Meta (Facebook) để xây dựng giao diện người dùng (User Interface). React cho phép xây dựng các ứng dụng web phức tạp với giao diện phản hồi nhanh.

2.5.2. Đặc trưng

  • Component-based: Chia giao diện thành các thành phần nhỏ, độc lập, có thể tái sử dụng.
  • Virtual DOM: So sánh sự thay đổi và chỉ cập nhật các phần tử thực sự thay đổi trên giao diện, tăng hiệu suất.
  • JSX: Cú pháp mở rộng cho phép viết HTML trong JavaScript, giúp code trực quan hơn.
  • Hooks: Cơ chế quản lý state và lifecycle trong Function Component (useState, useEffect, useContext...).

2.5.3. Ứng dụng trong SalonHub

Toàn bộ giao diện Frontend của SalonHub được xây dựng bằng React.js, bao gồm: trang khách hàng (đặt lịch, mua hàng), trang quản trị Admin (dashboard, quản lý nhân viên, dịch vụ), trang kế toán (đối soát, sổ quỹ). Mỗi trang được chia thành các Component tái sử dụng.

2.6. Vite

2.6.1. Định nghĩa

Vite là một công cụ build (build tool) thế hệ mới dành cho các ứng dụng web hiện đại, được tạo bởi Evan You — tác giả của Vue.js. Vite tận dụng ES Modules gốc của trình duyệt để phục vụ mã nguồn.

2.6.2. Đặc trưng

  • Khởi động nhanh: Máy chủ phát triển khởi động gần như tức thời, không cần đóng gói toàn bộ ứng dụng.
  • Hot Module Replacement (HMR): Cập nhật mã nguồn trên trình duyệt ngay lập tức khi chỉnh sửa, không tải lại trang.
  • Build tối ưu: Sử dụng Rollup để đóng gói production với kích thước nhỏ gọn.

2.6.3. Ứng dụng trong SalonHub

Vite được sử dụng làm công cụ build cho ứng dụng Frontend React của SalonHub, giúp quá trình phát triển nhanh chóng và triển khai production hiệu quả.

2.7. Zustand (Quản lý trạng thái)

2.7.1. Định nghĩa

Zustand là một thư viện quản lý trạng thái (State Management) nhỏ gọn, nhanh và có khả năng mở rộng dành cho React. Zustand cung cấp API đơn giản hơn nhiều so với Redux nhưng vẫn đáp ứng đầy đủ các nhu cầu quản lý trạng thái phức tạp.

2.7.2. Đặc trưng

  • API đơn giản: Tạo store chỉ với vài dòng code, không yêu cầu boilerplate phức tạp.
  • Không cần Provider: Khác với Redux và Context API, Zustand không cần bọc ứng dụng trong Provider.
  • Tương thích React Hooks: Sử dụng trực tiếp như một custom hook trong component.

2.7.3. Ứng dụng trong SalonHub

Zustand quản lý các trạng thái toàn cục: thông tin đăng nhập (authStore), giỏ hàng (cartStore), và thông báo hệ thống (notificationStore).

2.8. Tailwind CSS

2.8.1. Định nghĩa

Tailwind CSS là một CSS Framework theo hướng Utility-first, cung cấp các class tiện ích nhỏ để áp dụng trực tiếp vào phần tử HTML thay vì viết CSS tùy chỉnh trong file riêng.

2.8.2. Đặc trưng

  • Utility-first: Mỗi class đại diện cho một thuộc tính CSS duy nhất (ví dụ: p-4 = padding: 1rem).
  • Responsive: Hỗ trợ thiết kế đáp ứng với các tiền tố breakpoint (sm:, md:, lg:).
  • Purge CSS: Tự động loại bỏ các class không sử dụng khi build production, giảm kích thước file.

2.8.3. Ứng dụng trong SalonHub

Tailwind CSS được sử dụng để xây dựng toàn bộ giao diện của SalonHub, đảm bảo tính nhất quán về thiết kế, hỗ trợ responsive trên mobile/tablet/desktop, và tốc độ phát triển giao diện nhanh chóng.

2.9. MySQL

2.9.1. Định nghĩa

MySQL là một hệ quản trị cơ sở dữ liệu quan hệ (RDBMS — Relational Database Management System) mã nguồn mở, thuộc sở hữu của Oracle Corporation. MySQL sử dụng ngôn ngữ truy vấn có cấu trúc SQL để quản lý và thao tác dữ liệu.

2.9.2. Đặc trưng

  • Toàn vẹn dữ liệu: Hỗ trợ ràng buộc khóa chính, khóa ngoại, UNIQUE, NOT NULL.
  • Giao dịch ACID: Đảm bảo Atomicity (nguyên tử), Consistency (nhất quán), Isolation (cô lập), Durability (bền vững) cho các giao dịch phức tạp.
  • Hiệu suất cao: Tối ưu cho các truy vấn đọc, hỗ trợ indexing và query caching.

2.9.3. Ứng dụng trong SalonHub

MySQL lưu trữ toàn bộ dữ liệu của hệ thống: người dùng, lịch hẹn, đơn hàng, thanh toán, kho hàng và sổ quỹ. Tính năng Transaction được sử dụng khi xử lý thanh toán để đảm bảo tất cả thao tác cập nhật phải thành công đồng thời hoặc không thao tác nào được thực hiện.

2.10. Sequelize ORM

2.10.1. Định nghĩa

Sequelize là một thư viện ORM (Object-Relational Mapping) dành cho Node.js. ORM là kỹ thuật cho phép tương tác với cơ sở dữ liệu thông qua các đối tượng trong ngôn ngữ lập trình thay vì viết truy vấn SQL thuần.

2.10.2. Đặc trưng

  • Model Definition: Định nghĩa cấu trúc bảng dưới dạng các lớp JavaScript.
  • Associations: Hỗ trợ đầy đủ quan hệ: hasOne, belongsTo, hasMany, belongsToMany.
  • Migrations: Quản lý phiên bản cấu trúc database có kiểm soát.
  • Hooks: Cho phép can thiệp vào vòng đời của model (trước/sau khi tạo, cập nhật, xóa).

2.10.3. Ứng dụng trong SalonHub

Sequelize ánh xạ toàn bộ các bảng MySQL thành các Model JavaScript: User, Appointment, Order, Payment, Product, CashFlowTransaction... Các quan hệ (associations) giữa các Model giúp truy vấn dữ liệu liên bảng trực quan, ví dụ: lấy đơn hàng kèm thông tin khách hàng và sản phẩm chỉ với một truy vấn.

2.11. Socket.io

2.11.1. Định nghĩa

Socket.io là một thư viện cho phép giao tiếp hai chiều (bidirectional), dựa trên sự kiện (event-based) và thời gian thực (real-time) giữa Client và Server. Nó sử dụng WebSocket làm nền tảng và tự động fallback sang HTTP long-polling khi cần.

2.11.2. Đặc trưng

  • Giao tiếp hai chiều: Cả Client và Server đều có thể chủ động gửi dữ liệu cho nhau bất kỳ lúc nào.
  • Event-based: Giao tiếp qua các sự kiện tùy chỉnh (emit/on), dễ lập trình và mở rộng.
  • Room & Namespace: Cho phép gửi thông báo đến nhóm người dùng cụ thể.

2.11.3. Ứng dụng trong SalonHub

Socket.io được dùng để: thông báo cho Admin khi có lịch hẹn mới, thông báo cho khách hàng khi chuyển khoản được xác nhận thành công qua SePay, và cập nhật trạng thái đơn hàng theo thời gian thực mà không cần tải lại trang.

2.12. Cơ chế Webhook và Cổng thanh toán SePay

2.12.1. Định nghĩa

Webhook (hay HTTP Callback) là cơ chế cho phép một ứng dụng gửi dữ liệu tự động đến ứng dụng khác khi một sự kiện xảy ra. SePay là dịch vụ trung gian giám sát biến động số dư ngân hàng và gửi thông báo Webhook đến hệ thống của người dùng.

2.12.2. Đặc trưng

  • Cơ chế đẩy (Push): Khác với API polling (hỏi liên tục), Webhook chỉ gửi dữ liệu khi có sự kiện, tiết kiệm tài nguyên.
  • Thời gian thực: Dữ liệu được gửi ngay khi sự kiện xảy ra (giao dịch ngân hàng thành công).
  • Xác thực API Key: Đảm bảo chỉ có SePay mới có thể gửi dữ liệu đến endpoint của hệ thống.

2.12.3. Ứng dụng trong SalonHub

Khi khách chuyển khoản với nội dung chứa mã định danh (VD: SH12345, AP67890), SePay gửi Webhook đến endpoint /api/payments/sepay-webhook. Server SalonHub tự động: xác thực API Key, trích xuất mã đơn hàng/lịch hẹn từ nội dung chuyển khoản, cập nhật trạng thái thanh toán, ghi nhận vào sổ quỹ, và gửi thông báo Socket.io cho khách hàng.

2.13. JSON Web Token (JWT)

2.13.1. Định nghĩa

JSON Web Token (JWT) là một tiêu chuẩn mở (RFC 7519) định nghĩa cách truyền thông tin an toàn giữa các bên dưới dạng đối tượng JSON. Thông tin được ký số (digitally signed) nên có thể xác minh và tin cậy.

2.13.2. Đặc trưng

  • Cấu trúc 3 phần: Header (thuật toán ký), Payload (dữ liệu: userId, role, thời hạn), Signature (chữ ký số).
  • Tự chứa (Self-contained): Token chứa đủ thông tin xác thực, Server không cần lưu session.
  • Có thời hạn: Token có thời gian hết hạn, tăng tính bảo mật.

2.13.3. Ứng dụng trong SalonHub

Sau khi đăng nhập thành công, Server cấp JWT cho Client. Client gửi token trong Header Authorization của mỗi request để chứng minh danh tính. Middleware kiểm tra token để xác thực và phân quyền truy cập API theo vai trò (admin, staff, accountant, customer).

2.14. Bcrypt

2.14.1. Định nghĩa

Bcrypt là một hàm băm mật khẩu (password hashing function) được thiết kế bởi Niels Provos và David Mazières, dựa trên thuật toán mã hóa Blowfish. Bcrypt được đánh giá an toàn hơn MD5 và SHA nhờ cơ chế chống brute-force.

2.14.2. Đặc trưng

  • Salt tự động: Tạo chuỗi ngẫu nhiên kết hợp với mật khẩu trước khi băm, đảm bảo hai mật khẩu giống nhau có hash khác nhau.
  • Cost Factor: Cho phép điều chỉnh độ phức tạp tính toán, khi phần cứng mạnh hơn có thể tăng cost để chống brute-force.
  • Một chiều: Không thể giải ngược từ hash ra mật khẩu gốc.

2.14.3. Ứng dụng trong SalonHub

Tất cả mật khẩu người dùng được băm bằng Bcrypt với cost factor 10 trước khi lưu vào database. Khi đăng nhập, hệ thống so sánh mật khẩu nhập vào với hash đã lưu thông qua hàm bcrypt.compare(), đảm bảo mật khẩu gốc không bao giờ được lưu trữ dưới dạng văn bản thuần.

2.15. Mô hình ngôn ngữ lớn Llama 3.3 70B và Nền tảng Groq Cloud

2.15.1. Định nghĩa

Llama 3.3 70B Versatile là một mô hình ngôn ngữ lớn (Large Language Model — LLM) mã nguồn mở được phát triển bởi Meta AI. "70B" biểu thị mô hình có 70 tỷ tham số (parameters), cho phép hiểu và sinh ngôn ngữ tự nhiên với độ chính xác cao. Phiên bản "Versatile" được tối ưu cho đa nhiệm: hội thoại, tóm tắt, trả lời câu hỏi và phân tích dữ liệu.

Groq Cloud là nền tảng suy luận AI (AI Inference Platform) sử dụng chip LPU (Language Processing Unit) chuyên dụng, cho tốc độ xử lý mô hình ngôn ngữ nhanh gấp nhiều lần so với GPU truyền thống. Groq cung cấp API tương thích chuẩn OpenAI, giúp tích hợp dễ dàng vào ứng dụng.

2.15.2. Đặc trưng

  • Mã nguồn mở: Llama được Meta phát hành dưới giấy phép mở, cho phép sử dụng miễn phí trong nghiên cứu và thương mại.
  • Đa ngôn ngữ: Hỗ trợ tốt tiếng Việt trong hội thoại, phù hợp để xây dựng chatbot tư vấn cho khách hàng Việt Nam.
  • Tốc độ suy luận cao: Nhờ chip LPU của Groq, thời gian phản hồi cho mỗi câu hỏi chỉ trong vài trăm mili giây, mang lại trải nghiệm hội thoại mượt mà.
  • Kiểm soát đầu ra: Hỗ trợ tham số temperature để điều chỉnh mức độ sáng tạo/chính xác, và max_tokens để giới hạn độ dài câu trả lời.
  • API tương thích OpenAI: Sử dụng cùng chuẩn giao tiếp với OpenAI (chat.completions), giúp dễ dàng chuyển đổi giữa các nhà cung cấp mô hình.

2.15.3. Ứng dụng trong SalonHub

SalonHub tích hợp Llama 3.3 70B thông qua Groq Cloud API để xây dựng Chatbot Trợ lý ảo AI — một widget hội thoại nổi trên giao diện khách hàng. Chatbot có khả năng:

  • Tư vấn dịch vụ và báo giá chính xác dựa trên dữ liệu thực tế từ cơ sở dữ liệu (danh sách chi nhánh, bảng giá dịch vụ, sản phẩm đang bán).
  • Hướng dẫn khách hàng quy trình đặt lịch, hủy lịch, và các thông tin vận hành (giờ mở cửa, hotline).
  • Từ chối trả lời các câu hỏi ngoài phạm vi nghiệp vụ Salon để đảm bảo tính chuyên nghiệp.

Dữ liệu ngữ cảnh (context) được truy vấn trực tiếp từ database và cache trong 5 phút để tối ưu hiệu năng. Tham số temperature được đặt ở mức 0.3 (thấp) để AI bám sát dữ liệu thực tế, hạn chế bịa đặt thông tin.

2.16. Kỹ thuật Prompt Engineering

2.16.1. Định nghĩa

Prompt Engineering (Kỹ thuật thiết kế câu lệnh) là quá trình xây dựng và tối ưu các chỉ thị (prompt) gửi đến mô hình ngôn ngữ lớn nhằm hướng dẫn mô hình tạo ra câu trả lời chính xác, phù hợp với ngữ cảnh và yêu cầu cụ thể của ứng dụng.

2.16.2. Đặc trưng

  • System Prompt: Đặt vai trò và quy tắc hành vi cho mô hình ngay từ đầu cuộc hội thoại (ví dụ: "Bạn là Chuyên viên tư vấn của SalonHub").
  • Context Injection: Chèn dữ liệu thực tế vào prompt để mô hình trả lời dựa trên thông tin cập nhật, không dựa vào kiến thức huấn luyện sẵn.
  • Ràng buộc đầu ra: Quy định rõ định dạng, độ dài, và phạm vi trả lời (ví dụ: "Chỉ trả lời tối đa 4-5 câu", "Không trả lời câu hỏi lạc đề").
  • Few-shot / Zero-shot: Cung cấp hoặc không cung cấp ví dụ mẫu để mô hình học cách trả lời theo mong muốn.

2.16.3. Ứng dụng trong SalonHub

SalonHub sử dụng kỹ thuật Prompt Engineering để thiết kế System Prompt cho chatbot, bao gồm: định nghĩa vai trò ("Chuyên viên tư vấn chuyên nghiệp, tận tâm"), chèn dữ liệu thực tế từ database (chi nhánh, bảng giá, sản phẩm) vào ngữ cảnh, và thiết lập các quy tắc bắt buộc như chỉ báo giá dựa trên dữ liệu thực, từ chối khéo léo câu hỏi ngoài phạm vi, xưng hô lịch sự phong cách Luxury.
